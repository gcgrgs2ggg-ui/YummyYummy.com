# 《一碗海风的迁徙》· 网页版电子书

可画（Canva）竖版绘本 → 仿真翻页网页版电子书的成品站。88 页，A4 竖版比例（1:√2），
PC 端两两对开、手机端单页竖版，依赖零外链（库与字体全部本地）。

---

## 一、上传这些（其余不用传）

新建 GitHub 仓库后，把下面这些拖进去即可。**只有这 6 项是线上必需的：**

```
index.html
style.20261124.css
app.20261124.js
.nojekyll
assets/            ← 33 MB，全部页面与分享图
vendor/            ← page-flip 库（MIT），48 KB
```

`tools/` 和 `README.md` 传不传都不影响打开，可以不传（`tools/` 只在你要重新生成素材时才用）。

**不要**把原始 PNG（506 MB）或 `raw/` 传上去。

## 二、部署（GitHub Pages）

1. GitHub 新建仓库，**Public**，不要勾 README / .gitignore
2. 把上面 6 项拖进仓库根目录 → Commit
3. Settings → Pages → Source 选 `Deploy from a branch`，Branch 选 `main`、目录选 `/ (root)` → Save
4. 等 1–2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`

> `.nojekyll` 必须传。它是个空文件，用来阻止 Jekyll 过滤以下划线开头的路径。

## 三、上线后唯一要改的一处

`index.html` 里这两行还是占位符，微信/QQ 分享卡片要靠它们（抓取器不执行 JS，必须静态写死）：

```html
<meta property="og:url" content="https://<用户名>.github.io/<仓库名>/">
<meta property="og:image" content="https://<用户名>.github.io/<仓库名>/assets/og.20261124.jpg">
```

把 `<用户名>` / `<仓库名>` 换成实际的即可。不改也能正常看书，只是分享出去没有缩略图。

## 四、本地预览（改完先看效果）

不能直接双击 `index.html`（`file://` 下浏览器会拦截 canvas 取图）。在**本文件夹内**开终端：

```bash
cd ~/Desktop/一碗海风的迁徙-电子书
python3 -m http.server 8000
```

浏览器打开 `http://127.0.0.1:8000/`。手机看效果：电脑与手机连同一个 Wi-Fi，
手机访问 `http://<电脑局域网IP>:8000/`（`ipconfig getifaddr en0` 可查 IP）。

可用参数：`?diag=1` 显示尺寸诊断，`?open=toc` 直接打开目录，`?open=zoom` 打开放大层，
`#p=12` 直达第 13 页。

## 五、成书页序（88 页，偶数，未作任何增删）

| 位置 | 内容 | 来源文件 |
|---|---|---|
| 第 1 页 | 封面（单独成硬壳，占右半） | `封面.png` |
| 第 2 页 | 前环衬（纯空白） | `2.png` |
| 第 3–86 页 | 正文 84 页：扉页、目录、六章正文、小彩蛋、版权页 | `3.png` … `86.png` |
| 第 87 页 | 后环衬（纯空白，封底之前） | `空白页.png` |

PC 端对开配对：`[封面] [P2,P3] [P4,P5] … [P86,P87] [封底]`，双数在左、单数在右。
手机端一律单页，不拼对开。开头第一屏为「左空白 + 右扉页」，结尾倒数第二屏为「左版权页 + 右空白」。

当前目录合计 **88 页 / 33 MB**（1600×2263 WebP q88 与 1080×1527 q82 两档）。

## 六、要重新生成素材时

把可画导出的全部 PNG 解压进本文件夹下的 `raw/`，然后：

```bash
python3 tools/build_assets.py
```

脚本会：按页序排序（自动认「封面」「空白页」「空白页 (2)＝封底」）、统一裁成同一比例、
输出两档 WebP、生成 LQIP 占位、重写 `assets/manifest.v1.json`、重建分享图与图标。
书名/作者/简介写在 `tools/book.json`，改完重跑即可同步到页面标题与分享卡片。

改画布比例时同步改 `build_assets.py` 顶部的 `HI_W/HI_H/LO_W/LO_H`（当前 1600×2263 = A4 竖版）。

## 七、三条固定规则（不是 bug）

1. **封面、封底不居中**：库的硬壳页固定占右半（封面）/ 左半（封底），空出的半边是书壳材质。
   强行居中会和库的坐标计算打架，翻页时位置会漂。
2. **总页数必须是偶数**：`showCover` 模式下奇数页会让封底被挤进最后一个对开，翻到末页报错。
   当前 88 页，正好。
3. **手机和 PC 是同一个翻页实例自动切换**，不销毁不重建，所以横竖屏来回转不会丢页码、
   不会出现半张对开。

## 八、验收清单

- [ ] PC 首屏只有封面一张、在右半，左半是深色书壳
- [ ] PC 每个对开左页是 P2/P4/P6…（双数），右页是 P3/P5/P7…（单数）
- [ ] 中缝有暗部、左右页衔接看不出接缝
- [ ] 末屏封底单独在左半，「下一页」按钮变灰
- [ ] 手机竖屏始终单页，双指放大不触发翻页
- [ ] 横竖屏反复切换：页码不跳、不出现半张对开
- [ ] 目录 88 张缩略图都能打开对应页
- [ ] 「放大」层清晰，Esc 或点图可关
- [ ] 手机 4G 下首屏 3 秒内可翻页（首屏只加载封面 + 相邻 4 页）

## 九、容易踩的坑

| 坑 | 说明 |
|---|---|
| 直接双击 html | `file://` 下取图失败，必须用 `http.server` |
| 忘了 `.nojekyll` | 带下划线的路径会被 Jekyll 忽略 |
| 用 `?v=123` 做缓存刷新 | GitHub Pages 的 CDN 会忽略查询串，改文件名（如 `style.20261125.css`）才可靠 |
| 改了图片但没改名 | CDN 缓存最长 10 分钟，等一会儿或改文件名 |
| 素材用 PNG 直接上传 | 33 MB → 500 MB，仓库会变很卡 |
| 页数改动后没重跑脚本 | `manifest` 与 DOM 页数不一致会直接报错，跑一次 `build_assets.py` 即可 |
